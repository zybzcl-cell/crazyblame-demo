# 疯狂甩锅

把老板甩过来的锅，一口一口甩回去。**3 秒准备 + 42 秒正式游戏 ≈ 45 秒一局**的轻量解压游戏。

这是一个**完全独立**的 Godot 项目（与《老板来了》没有任何运行时依赖）：
自己的 `project.godot`、菜单、游戏场景、结算、存档、音效、配置、测试和文档。

---

## 快速开始

```bash
# 直接用 Godot 打开这个目录，或者命令行运行
/Applications/Godot.app/Contents/MacOS/Godot --path .

# 跑全部自动化测试（含真实窗口截图）
./run_all_tests.sh

# 没有图形界面时（CI / 服务器）
./run_all_tests.sh --no-window

# 重新生成本地合成音效（覆盖 assets/audio/）
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . res://tools/generate_sfx.tscn

# 平衡参考报告（三种模拟玩家各打 3 局）
/Applications/Godot.app/Contents/MacOS/Godot --headless --path . res://tools/balance_report.tscn
```

第一次用命令行运行前建议先 `--headless --import` 导一次资源（`run_all_tests.sh` 会自动做）。

## 界面构图（720×1280 的空间分配）

竖屏的空间预算集中在 [scripts/core/layout_data.gd](scripts/core/layout_data.gd) 一个文件里，
场景、HUD、老板、办公室背景都从同一份预算取坐标（不再是各处硬编码）。比例是相对值，
所以在 390×844 的手机、720×1558 的长屏、2275×1280 的桌面宽窗口上都成立：

```
 0.030 ┃ 顶部 HUD：返回 / 倒计时 / 连击 / 阶段
 0.096 ┃ 老板精神状态条 + 阶段名 + 数值
 0.140 ┃ 老板台词
 0.164 ┃ ┌ 办公室空间（墙）
       ┃ │   窗户（左）、本月业绩白板（右）都挂在墙上，带挂件投影
       ┃ │   老板坐在办公桌后面，桌子下沿正好落在墙 / 地板交界上
 0.500 ┃ └ 墙 / 地板分界（踢脚线 + 桌子接触阴影）
 0.510 ┃ ┌ 甩锅操作区（地板上的办公区地毯）
       ┃ │   锅在这里出现、飘移、被抓、被拖、被甩回老板
 0.918 ┃ └
 0.926 ┃ 底部辅助信息：总分 / 命中 / 失误 / 命中率
```

几条硬约束（`tests/composition_test.gd` 会逐条断言，四种屏幕比例各测一遍）：

- 老板整体落在办公室空间内：头顶在状态条下方，桌沿贴着地板线，人物不侵占操作区；
- 窗户与白板挂在墙上、位于桌面上方，白板不会压住老板的头；
- 甩锅操作区完全在桌沿下方，高度不低于屏高的 40%，宽度不低于内容列的 85%；
- 顶部 / 底部 HUD 都不压老板、不压操作区，所有文字都在自己那一格里（小屏自动收字号）；
- 老板的受击判定圈完全在操作区上方，拖上去就能命中、不会误触。

玩家第一眼看到的顺序是：**老板 → 锅 → 甩锅操作区 → HUD**。背景只做空间交代
（冷灰蓝墙面 + 暖木地板 + 压低对比度 + 四角压暗），不跟核心元素抢视觉重量。

**操作（鼠标与触摸是同一套逻辑）**

1. 老板从桌子后面把锅甩过来（锅先飞进下半屏的场地）。
2. **点住锅**抓住它（每口锅的抓取判定圈大小不同）。
3. **拖到老板身上**松手 —— 或者朝老板快速划一下**甩出去**。
4. 命中：老板挨锅、掉精神状态、掉表情；失误：锅凉了 / 手滑了 / 甩歪了。

- 同一时间**只能拿一口锅**（所以「先处理哪一口」是真正的取舍）。
- 轻轻放下不算失误（手机上手指抖一下不会被罚）；失误会断连击。
- 鼠标：按住左键拖动；触摸：单指点住拖动（第二根手指不会抢锅）。

**45 秒节奏（`scripts/core/pot_data.gd` 的 PHASES）**

| 时间 | 阶段 | 生成间隔 | 同屏上限 | 锅的存活 | 出场锅种 |
| --- | --- | --- | --- | --- | --- |
| 0–10s | 热身 | 1.50s | 1 | ×1.00 | 普通锅、破锅 |
| 10–20s | 加速 | 1.15s | 3 | ×0.85 | ＋平底锅 |
| 20–30s | 混合 | 0.95s | 4 | ×0.72 | ＋铁锅、压力锅 |
| 30–37s | 高压 | 0.78s | 5 | ×0.60 | 五种锅混合，连击倍率 ×1.15 |
| 37–42s | **疯狂甩锅** | 0.55s | 6 | ×0.50 | 五种锅，连击倍率 ×1.5，整屏泛红 |

## 五种锅（不是换贴图，手感真的不一样）

| 锅 | 伤害 | 飘移速度 | 跟手 | 抓取判定 | 存活 | 特点 |
| --- | --- | --- | --- | --- | --- | --- |
| 普通锅 | 5 | 130 | 11.0 | 62 | 8.5s | 基础目标，最好抓也最好甩 |
| 铁锅 | 15 | 82 | 4.6 | 74 | 10.5s | 又大又慢很好抓，**拖起来明显死沉**，握着它就没手接别的锅 |
| 平底锅 | 8 | 215 | 14.0 | 52 | 6.5s | 飞得快、存活短，考验反应 |
| 压力锅 | 6 → 24 | 112 | 8.5 | **46** | 8.5s | 判定圈最小最难抓；握在手里蓄力，**蓄满伤害 24**、有专属爆击反馈 |
| 破锅 | 3 | **265** | **19.0** | 54 | 6.0s | 又小又快，单次伤害最低，但**一次涨 2 连击**，是连击发动机 |

数值全部在 `scripts/core/pot_data.gd` 一处定义，测试直接对着同一份数据断言（见 `tests/pot_test.gd`）。

## 老板：七个状态 + 一整套表演

老板不是血条数字，而是这个游戏的 IP 核心。血量比例 → 七个阶段，每个阶段**表情、眉毛、嘴、眼镜角度、领带、手臂姿势、桌上道具、特效**全都不一样：

| 阶段 | 表情 | 表演 |
| --- | --- | --- |
| 1 得意 😀 | 眯眼笑 | 抱着手、咖啡冒着热气、闪光 |
| 2 疑惑 🙂 | 一挑眉 | 歪头、手托下巴、眼镜开始下滑 |
| 3 不爽 😐 | 皱眉撇嘴 | 抱手、抖腿、文件开始晃 |
| 4 愤怒 😠 | 瞪眼倒八字眉 | 青筋、耳朵冒烟、一拳撑在桌上 |
| 5 暴怒 😡 | 呲牙 | 站起来挥拳、领带歪掉、头发炸开、咖啡乱晃 |
| 6 疲惫 😫 | 眼睛转圈 | 扶额、满头汗、身体往下塌、眼镜滑到鼻尖 |
| 7 崩溃 😵‍💫 | @_@ | **趴桌**、眼镜歪掉、头发乱成鸡窝、桌上东西翻倒、头顶转星星 |

每次挨锅还会叠加：后仰抖动、白光、桌面物品晃动、挨打表情（X 眼 + 张嘴 0.3 秒）、
**重锅会真的「扣在老板头上」**（铁锅 / 压力锅）。

舞台上还有一条暗线：白板上的「本月业绩」折线会跟着老板的精神状态一路往下掉，打崩老板时白板直接写「完蛋」。

## 计分与评级

**总分**（几千分级别）不是「命中次数 × 常数」，每次命中算的是：

```
得分 = 锅的基础分 × 反应速度加成(最高 +35%) × 连击倍率(最高 3.0×) × 疯狂阶段(×1.5) × 完美蓄力(×1.2)
```

**评级 0~100** 由五个维度加权（`scripts/core/score.gd`）：

| 维度 | 满分 | 说明 |
| --- | --- | --- |
| 命中率 | 34 | 命中 /（命中 + 失误） |
| 最高连击 | 18 | 连击 24 封顶 |
| 老板受到的伤害 | 22 | 打满老板精神值封顶 |
| 疯狂阶段命中 | 14 | 最后 5 秒的表现 |
| 锅的难度构成 | 12 | 只打普通锅拿 0 分，敢接铁锅 / 压力锅才拿得到 |

评级：S ≥ 90 / A ≥ 78 / B ≥ 64 / C ≥ 48 / D。称号依次是
「甩锅之神 / 甩锅高手 / 熟练背锅侠 / 手忙脚乱 / 被锅甩了一脸」。

结算卡上会显示：总分、评级、老板受到的总伤害与剩余精神状态、命中 / 失误 / 命中率、最高连击、
疯狂阶段命中、本局时长与结束原因、**每种锅甩回去了几口**、老板最终状态，以及新纪录 / 解锁提示。

## 解锁与成长

只有轻量成长，不做数值养成 —— 核心仍然是「靠技术玩得更好」：

- 默认解锁：普通锅、平底锅、破锅（第一局就能看到不同锅）。
- **铁锅**：累计命中 12 口锅后自动解锁（约一局）。
- **压力锅**：一局打出 10 连击后自动解锁。
- 主菜单的「锅图鉴」会显示五种锅的数值、难度、解锁进度；解锁之后的锅还能**临时停用**
  （比如不想被压力锅打乱节奏），这是玩法选择而不是数值取舍。

存档里累计：最高分 / 最高评级 / 最高连击 / 累计局数 / 累计命中 / 累计失误 / 累计甩回锅数 /
累计伤害 / 每种锅的累计命中 / 累计游玩时长 / 最后游玩时间。

## 存档

- 位置：`user://crazy_blame_save.json`（macOS 是 `~/Library/Application Support/Godot/app_userdata/疯狂甩锅/`）。
- 格式：Godot 原生 `FileAccess` + JSON，明文、带 `version` 字段，字段只增不减。
- **坏存档永远不会让游戏崩**：文件不存在 / 不是 JSON / 类型不对 / 数值越界 / 不认识的锅 id，
  一律安全退回默认值（`tests/progress_test.gd` 里专门测了这些）。
- 跨进程验证：一个进程写、另一个进程读，确认「关掉游戏成绩还在」（`tests/save_persistence_test.gd`）。
- 不需要账号、不需要联网、不写任何服务器。

## 音效与美术

- **音效**：21 个音效全部由 `tools/generate_sfx.gd` **本地合成**（16bit / 44.1kHz 单声道 WAV），
  不下载任何第三方素材，所以不涉及第三方授权（见 `THIRD_PARTY.md`）。
  播放统一走 `AudioManager`：小池子复用、同一音效限流、随机音高、连击升调，
  并且尊重设置里的声音开关；无窗口（测试）时自动静音。
- **美术**：老板、锅、特效、办公室背景全部用 Godot 原生绘制（`_draw`），
  三者各自独立成节点（`scripts/game/boss.gd` / `pot.gd` / `fx_layer.gd`），
  以后换成正式美术只需要替换对应节点，不用动玩法代码。
- **中文显示**：项目内嵌了一整套中文字体 **Noto Sans SC**（SIL OFL 1.1，见 `assets/fonts/OFL.txt`），
  桌面与 Web 用的是同一个字体文件 —— 浏览器里没有系统字体可用，不内嵌就会出现「豆腐块」。
  `tests/font_test.gd` 会静态扫描全部源码里出现的非 ASCII 字符、再遍历运行时界面的每一段文字，
  逐个确认字体能画出来；实机截图还会画出两个不同的汉字做像素比对。
- **没有 emoji**：表情符号在 Web 端没有字体可用会变方框，所以老板的表情全部是**画出来的脸 + 阶段文字**
  （阶段文字还会按 绿→黄→红 变色），文案里不留任何 emoji。

## 平衡参考

`tools/balance_report.gd` 用四种模拟玩家各打 3 局（模拟玩家会优先处理快凉了的锅、
按固定「处理一口锅所需时间」操作）：

| 模拟玩家 | 处理一口锅 | 平均总分 | 平均评级 | 命中 / 失误 | 打到老板 |
| --- | --- | --- | --- | --- | --- |
| 熟练玩家 | 0.55s | ~21300 | 89（A/S） | 41 / 0 | 237 / 260，3 局里能打崩 1 局 |
| 普通玩家 | 0.95s | ~15600 | 80（A） | 36 / 0.3 | 204 / 260 |
| 手忙脚乱 | 1.70s | ~5600 | 59（C） | 23 / 6.7 | 142 / 260 |
| 专挑硬锅 | 0.75s | ~21200 | 87（A） | 39 / 0.3 | 251 / 260，3 局里能打崩 1 局 |

结论：手忙脚乱会掉到 C，「稳、准、敢接硬锅」能上 A/S 并且真的把老板打到趴桌 ——
也就是「靠技术玩得更好」这条线是成立的。

## Web 试玩版（手机浏览器直接玩）

```bash
# 1. 构建（产物在 web_build/）
./tools/build_web.sh

# 2. 本地起一个静态服务器（随便什么静态服务器都行）
cd web_build && python3 -m http.server 8777
# 然后浏览器打开 http://127.0.0.1:8777/index.html
# 想用手机试玩：让手机和电脑在同一个 Wi-Fi，用电脑的内网 IP 访问同一端口

# 3. 部署：把 web_build/ 整个目录上传到任何静态网页服务器
#    GitHub Pages / Netlify / Vercel / 对象存储 / 自己的 Nginx 都可以
#    注意 .wasm 要以 application/wasm 返回（主流静态托管默认就是对的）
```

构建做了什么：

1. `Godot --export-release Web` 导出 `index.html / index.js / index.wasm / index.pck`；
2. 给 `index.html` 打一层**移动端补丁**（`tools/web_postprocess.gd`）：
   - `viewport-fit=cover` + `env(safe-area-inset-*)`：刘海 / 状态栏 / 底部小横条不会裁掉画面；
   - 禁用页面滚动、双击缩放、长按菜单、橡皮筋回弹，画布跟随窗口（`canvas_resize_policy=2`）；
   - 一张「点击开始」启动页：它不吃触摸事件（`pointer-events:none`），
     所以这一下点击会直接落到游戏画布上 —— 既满足浏览器「音频需要用户手势」的要求，
     也能顺势点到主菜单的「开始甩锅」；
   - 与游戏一致的深色底 + 加载进度样式。

Web 端的几处适配：

| 关注点 | 做法 |
| --- | --- |
| 中文显示 | 内嵌 Noto Sans SC（8.3MB），不依赖系统字体，浏览器里不会出现方框 |
| 存档 | Godot Web 的 `user://` 走 IndexedDB（IDBFS）；浏览器禁用存储时 `SaveStore` 静默失败，不会影响这一局能不能玩 |
| 音效 | 由「点击开始」这一次用户手势解锁音频；`AudioManager` 依旧是唯一出口 |
| 震动 | `Haptics` 在 Web 上走 `navigator.vibrate`（iOS Safari 不支持就静默跳过），失败不影响游戏 |
| 触摸 / 鼠标 | 触摸与鼠标共用同一套 Pointer 逻辑；项目里关掉了「触摸再模拟成鼠标」，避免一次点击算两次 |
| 无线程依赖 | `variant/thread_support=false`，因此不需要 COOP/COEP 响应头，任何静态托管都能跑 |

### 浏览器实测（本机真实验证）

在 **macOS Safari（真实浏览器、真实引擎）** 里加载 `web_build/` 并做了启动 + 交互自检
（`tests/web_probe.html` 把结果写进页面标题，用 AppleScript 读回）：

- 引擎启动：`index.wasm / index.pck` 全部拉取成功，画布 390×844，WebGL 上下文创建成功，**0 个 JS 报错**；
- 画面确实渲染：读取画布像素，菜单的金色标题 / 强调色像素占比 ≈ 1.0%；
- 鼠标路径：`mousedown/mouseup/click` → 「开始甩锅」→ **游戏场景真的开始了**（画面差异 0.074，远高于动画本底 0.011），
  再点左上角「×」→ **回到主菜单**（金色标题回来）；
- 触摸路径：`pointerType=touch` 的指针事件同样能启动游戏（真机就是这条路径）；
- 页面补丁生效：`viewport-fit=cover`、`touch-action:none`、启动页点击后消失。

**没能在本机验证的部分（不假装验证过）**：

- 桌面 **Chrome**：这台机器没装 Chrome/Chromium，只做了配置与代码层面的兼容性检查；

  与 `visualViewport` 支持已在 Safari 里确认可用，但实际 inset 数值需要真机确认）；
- **浏览器里的完整一局**：自检覆盖到「进入游戏场景」，没有在浏览器里打满 45 秒（桌面版与 Godot 测试里已完整覆盖）。

## 移动端 / 未来上架

- 竖屏 720×1280 设计分辨率 + `canvas_items` / `expand`，任何屏幕比例都能自适应（布局全部按屏幕算）。
- **触摸是核心操作**，与鼠标共用同一套 Pointer 逻辑；`emulate_mouse_from_touch` 关闭，避免一次点击算两次。
- 震动集中在 `Haptics`（桌面静默、移动端调用系统接口），上 Android / iOS 只影响这一个文件。
- 渲染器用 `gl_compatibility`，对低端机与移动端更友好。
- 为未来留的口子：结算统一走 `BlameGame.finished` 信号 + `ProgressManager.register_game()`
  （将来接排行榜 / 分享只需订阅，不改玩法）；存档带 `version` 且字段只增不减；
  音效集中在 `GameConfig.SOUNDS`（换正式音源只改这一处）；老板 / 锅 / 特效是独立节点（换美术不动玩法）。
- 第一版**刻意不做**：联网、账号、服务器、广告 SDK、内购、在线排行榜、社交分享。

## 与《老板来了》的关系
